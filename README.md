# Awesome Nonprofit Salesforce

A curated list of open-source tools, packages, and resources for nonprofits running Salesforce - NPSP, Nonprofit Cloud, and the Agentforce Nonprofit layer built on top of it. Built for npsp to nonprofit cloud migration work, npsp field mapping, agentforce nonprofit data model questions, and general salesforce nonprofit tools discovery.

Two competing lists already cover general Salesforce ([mailtoharshit/awesome-salesforce](https://github.com/mailtoharshit/awesome-salesforce), stale since 2021; [Clientell-Ai/awesome-salesforce](https://github.com/Clientell-Ai/awesome-salesforce), more current but not nonprofit-focused). This one is scoped to the nonprofit side specifically, and it tells you when an entry stops being maintained instead of letting it rot silently.

## How this list is maintained

Every entry lives in [`data/entries.yml`](data/entries.yml) - that file is the source of truth, and this README is generated from it by [`scripts/generate_readme.py`](scripts/generate_readme.py). Don't hand-edit the list below; edit the YAML and regenerate.

A separate weekly job checks every GitHub-hosted entry's real status - archived or not, last push date, star count - and writes the result to [`docs/STATUS.md`](docs/STATUS.md). An entry with no push in 18+ months gets flagged "may be unmaintained"; an archived repo gets flagged "archived." Flags don't get an entry removed - see [CONTRIBUTING.md](CONTRIBUTING.md) for why - they just tell you what you're getting into before you install something.

### Migration & Data Model

- **[NPSP](https://github.com/SalesforceFoundation/NPSP)** - The official, actively maintained Nonprofit Success Pack source. Start here before assuming a fork or mirror is more current - several exist and most are stale copies.
- **[NPSP to Nonprofit Cloud Field Map](https://github.com/clear-concise-carmona/npsp-to-nonprofit-cloud-field-map)** - Source-cited, field-level crosswalk between every NPSP object/field and its Nonprofit Cloud equivalent, with confidence tags on every row. _(maintained by Clear Concise Consulting)_
- **[NPSP Migration Readiness Scanner](https://github.com/clear-concise-carmona/npsp-migration-readiness-scanner)** - sf CLI plugin that scores an org's NPSP-to-Nonprofit-Cloud migration readiness from 0-100 and lists the specific blockers found. _(maintained by Clear Concise Consulting)_
- **[Relationships](https://github.com/SalesforceFoundation/Relationships)** - NPSP's Relationships package - tracks reciprocal relationships between contacts (spouse, employer, etc.), a common migration pain point since Nonprofit Cloud models this differently.
- **[Data Lake for Nonprofits](https://github.com/salesforce-misc/Data-Lake-for-Nonprofits)** - Reference architecture for standing up a data lake against nonprofit Salesforce data, useful when a migration needs data warehoused outside the org during the transition.
- **[Declarative Lookup Rollup Summaries (DLRS)](https://github.com/SFDO-Community/declarative-lookup-rollup-summaries)** - The de facto standard for declarative cross-object rollups in NPSP orgs. Worth auditing before any Nonprofit Cloud migration since Nonprofit Cloud's rollup model differs from NPSP's.

### Data Quality & Dedupe

- **[Nonprofit Data Quality Scorecard](https://github.com/clear-concise-carmona/nonprofit-data-quality-scorecard)** - Apex + LWC package scoring an org on 10 data quality metrics (duplicates, stale contacts, orphan gifts, missing GAU allocations, and more), detecting NPSP vs. Nonprofit Cloud at runtime and branching queries accordingly. _(maintained by Clear Concise Consulting)_
- **[DupeDedupe](https://github.com/SFDO-Community-Sprints/DupeDedupe)** - Community Sprint project on managing duplicates in Salesforce nonprofit orgs. Check the status flag below before relying on it - Community Sprint projects vary widely in upkeep.

### AI & Agentforce

- **[Agentforce SDK](https://github.com/salesforce/agent-sdk)** - Official Python SDK for creating, managing, and running Agentforce agents. General-purpose, not nonprofit-specific, but the current entry point for anything custom built on Agentforce.
- **[agentscript](https://github.com/salesforce/agentscript)** - Open, schema-driven language for configuring agent orchestration. Same caveat as the SDK above - general Agentforce tooling, not nonprofit-specific, but relevant to anyone building on Agentforce Nonprofit.
- **[Agentforce Archive Agent](https://github.com/heroku-reference-apps/agentforce-archive-agent)** - Worked example extending Agentforce with a custom Heroku action for unstructured-data processing - a reasonable template if you're building a custom Agentforce action.
- **[Agentforce Nonprofit Governance Kit](https://github.com/clear-concise-carmona/agentforce-nonprofit-governance-kit)** - Free 15-question weighted AI governance readiness scorecard for Agentforce, an sf CLI plugin with read-only org checks (Einstein Trust Layer settings, prompt template and agent inventory, consent field coverage), and four forkable policy templates covering AI usage, data handling and consent, escalation and human review, and incident response. _(maintained by Clear Concise Consulting)_

### Grants & Fund Management

- **[Outbound Funds Module](https://github.com/SalesforceFoundation/OutboundFundsModule)** - Community-maintained foundation for managing funds an organization awards - grants, scholarships, internal funding.
- **[Outbound Funds Module Site](https://github.com/SalesforceFoundation/OutboundFundsModuleSite)** - Fundseeker-facing Experience Cloud portal template that pairs with Outbound Funds Module.
- **[Program Management Module (PMM)](https://github.com/SalesforceFoundation/PMM)** - Service delivery and outcomes tracking for programs, cohorts, and case management.

### Fundraising & Payments Integrations

- **[FinDock for Fundraising Flows](https://github.com/FinDockLabs/findock-for-fundraising-flows)** - Flow and component examples for wiring FinDock payments into Nonprofit Cloud Gift Commitment schedules.
- **[FinDock Experience Cloud Examples](https://github.com/FinDockLabs/findock-experience-cloud-examples)** - Code examples for integrating FinDock donation processing into Experience Cloud donor sites.

### Accessibility

- **[sa11y](https://github.com/salesforce/sa11y)** - Salesforce's own automated accessibility testing libraries - worth wiring into CI for any nonprofit build with a public donor or client-facing portal.

### Volunteer Management

- **[Volunteers for Salesforce (V4S)](https://github.com/SalesforceFoundation/Volunteers-for-Salesforce)** - The standard managed package for volunteer recruitment, scheduling, and hour tracking on NPSP orgs.
- **[PMM + V4S Recipe](https://github.com/SFDO-Community-Sprints/PMM-V4S)** - Community Sprint recipe for connecting Program Management Module and Volunteers for Salesforce. Flagged archived below - treat as a reference, not a maintained integration.

### Learning Resources

- **[Salesforce.org Open Source Commons](https://sfdo-community-sprints.github.io/)** - The hub coordinating every Community Sprint project in this list - where new sprints, projects, and events get announced.
- **[Trailhead: Agentforce Nonprofit Basics](https://trailhead.salesforce.com/content/learn/modules/nonprofit-cloud-basics)** - Official starting module for Agentforce Nonprofit (formerly Nonprofit Cloud).
- **[Trailhead: Nonprofit Cloud Learning Resources Quick Look](https://trailhead.salesforce.com/content/learn/modules/nonprofit-cloud-learning-resources-quick-look)** - Salesforce's own curated map of nonprofit-cloud learning content.
- **[Nonprofit Salesforce How-To Series](https://github.com/SFDO-Community-Sprints/Nonprofit-Salesforce-How-To-Series)** - Short how-to videos for nonprofit Salesforce admins and users, produced at ongoing Community Sprints.
- **[Salesforce Trailhead Solutions](https://github.com/artysta/salesforce-trailhead-solutions)** - Worked Trailhead exercise solutions - handy reference when a module's checker gets stuck.
- **[DEI Framework](https://github.com/SFDO-Community-Sprints/DEI-Framework)** - Community Sprint project drafting a diversity/equity/inclusion framework for the nonprofit Salesforce ecosystem. Flagged archived below.

## Status-check automation

- [`scripts/check_status.py`](scripts/check_status.py) queries the GitHub API for every repo entry and regenerates [`docs/STATUS.md`](docs/STATUS.md).
- [`.github/workflows/check-status.yml`](.github/workflows/check-status.yml) runs that script weekly and commits the result automatically.
- [`.github/workflows/validate-readme-sync.yml`](.github/workflows/validate-readme-sync.yml) runs on every PR that touches `data/entries.yml` and fails if `README.md` wasn't regenerated to match.
